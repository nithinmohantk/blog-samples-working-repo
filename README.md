## Verification status

Not everything here has been compiled or run. The state at the time of the first commit:

* Python: the tests in every folder pass on Python 3.13.
* C# in `fhir-openehr`, `openehr-aql-to-fhir` and `clinical-queries`: compiled and run on the .NET 10 SDK.
* `fhir-facade-openehr`: self-test run on the .NET 10 SDK; the API built on the .NET 10 SDK image and run in Docker against EHRbase 2.39.0, where the Python test client passed 20 of 20 checks. Not deployed to Azure and not tested with Microsoft Entra ID.
* C# in `meai-two-clouds`, `a2a-mcp-interop/dotnet` and `secure-remote-mcp/dotnet`: **not yet compiled**. They depend on NuGet packages; run `dotnet build` before relying on them.
* `clinical-queries/live`: AQL run on EHRbase 2.39.0 and FHIR searches run on HAPI FHIR 8.6.0, both local. See `RESULTS.md` there for what passed, what failed and what was not covered.
* `azure-api-for-fhir-migration`: script tests and validator self-test pass; the validator was run in Docker against two HAPI FHIR servers. Not run against either Azure service.
* `fhir-events-azure-functions`: core self-test and Python rule pass; the Function App was built and run in Docker with PostgreSQL and HAPI FHIR, where the replay script passed 22 of 22. Events were built by the script, not by Event Grid.
* `fhir-validation-ci`: run in GitHub Actions (`.github/workflows/fhir-validation.yml`) with the HL7 validator and the Firely SDK against the IPS 2.0.0 profiles; see its README for the results. Only IPS, only single resources.
* `clinical-coding-structured-outputs`: tests pass in both languages, the Azure OpenAI client code builds, and the FHIR output passes the HL7 validator with a terminology server, all in GitHub Actions. **No call to Azure OpenAI was made**; the model responses in the fixtures are hand-written.
* `dotnet11-for-architects`: built and run in GitHub Actions on SDK 11.0.100 beside the .NET 10 runtime; see its README for what was observed. Timings there are single runs and are not performance claims.
* `csharp15-unions`: tests, experiments and a deliberately failing build run in GitHub Actions on SDK 11.0.100; see its README for each result.
* `terraform-testing-ci`: tests, mutations and policy gate run in GitHub Actions on Terraform 1.16.3 and OpenTofu 1.12.6 against a mocked provider. Nothing is applied to a real account.
* `terraform-two-clouds`: contract and cloud-specific tests run in GitHub Actions on Terraform 1.16.3 and OpenTofu 1.12.6 against mocked AWS and AzureRM providers. Nothing is applied to a real account.
* `terraform-vs-opentofu`: 24 experiments run on Terraform 1.16.5 and OpenTofu 1.13.1 in GitHub Actions; see its README for the matrix.
* `dotnet10-on-lambda`: three builds of one function run in the AWS Lambda base images under the Runtime Interface Emulator, in GitHub Actions. Timings are from the runner, not from Lambda. SnapStart is not exercised.
* `sqlserver2025-vector-json`: experiments run against the SQL Server 2025 container (the image built most recently before 25 April 2026) in GitHub Actions, with synthetic vectors and documents. Timings are from the runner.
* `gpt52-codex-context-budget`: token counts, cost arithmetic and a Responses API client tested against a local stand-in in GitHub Actions. No request is sent to any model.
* `gpt6-codex-model-routing`: cost arithmetic on published prices, and the Codex CLI run in GitHub Actions against a local stand-in that plays a script. No model is called.
* `one-agent-three-frameworks`: Microsoft Agent Framework, LangGraph and Google ADK run in GitHub Actions against a scripted stand-in on localhost. No model is called.
* `mcp-contract-testing`: every MCP server is a local process started in GitHub Actions on stdio or 127.0.0.1. No model is called.

## Healthcare samples

The FHIR and openEHR samples use synthetic data only. They are teaching material, not clinically validated software, and must not be used for clinical decisions.
